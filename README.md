# Обработка заказов

Программа принимает книги Excel в форматах `.xlsx`, `.xlsm`, `.xlsb`, `.xls`,
`.xltx` и `.xltm`. Результат обработки всегда сохраняется как `.xlsx`.
Для `.xlsx`/`.xlsm`/`.xltx`/`.xltm` сохраняется исходная структура и оформление;
старые `.xls` и бинарные `.xlsb` сначала конвертируются в рабочую книгу, поэтому
их исходное оформление может быть потеряно. VBA-макросы любых входных книг в
итоговый `.xlsx` не переносятся.

Программа распределяет строки/столбцы заказа по маршрутам доставки,
раскрашивает адреса, создаёт отдельные листы по каждому маршруту и
ведёт лог обработки.

Перед фактической обработкой приложение строит **предварительный просмотр**:
показывает выбранный режим, число строк и совпадений, найденные магазины,
объём по маршрутам, конфликты и неизвестные магазины. В консольной и tkinter-версиях обработка
запускается только после подтверждения; в веб-дашборде кнопку подтверждения
можно нажать после просмотра. Изменение режима или загрузка нового файла
сбрасывает старый просмотр. До подтверждения итоговая книга, лог и история
обработок не изменяются.

Модуль `python-calamine` устанавливается автоматически из `requirements.txt` и
нужен для чтения `.xls` и `.xlsb`.

## Резервные копии

В веб-дашборде и tkinter откройте раздел **Резервные копии**. Доступны ручное
создание ZIP-копии, выбор папки хранения, проверка архивов и восстановление
после отдельного предупреждения. Перед восстановлением автоматически создаётся
страховочная копия текущего состояния.

В архив попадают только файлы состояния: `volume_history.json`,
`processed_files.json`, `mail_items.json` и файлы почтового кеша,
`route_backups.json`, `settings.json`, списки магазинов и, если существует,
`mail.json`. Рабочие книги, PDF, фотографии и логи намеренно не копируются.
Архив содержит `manifest.json` с версией формата, датой и перечнем файлов.

`config/mail.json` может содержать пароль приложения. Такие архивы помечаются
в интерфейсе и не должны передаваться другим людям. Восстановление заменяет
текущее состояние; архивы с небезопасными путями, неизвестными файлами или
повреждённым JSON отклоняются до изменения данных. По умолчанию архивы хранятся
в `data/backups`.

Перед фактической установкой обновления через страницу **Версия** приложение
создаёт автоматическую копию с причиной «перед обновлением». Если создать её
нельзя, обновление не запускается.


Для обычного запуска на **Windows 10/11 x64** понадобятся:

- **Python 3.10–3.14 x64** — обязательно;
- **Git** — рекомендуется, чтобы скачать проект и потом обновлять его одной
  командой;
- **Node.js LTS** — рекомендуется для frontend-инструментов и диагностики.
  `start_dashboard.bat` напрямую Node.js не использует: Reflex обычно сам
  загружает нужный frontend-тулчейн, поэтому отдельно выполнять `npm install`
  для этого проекта не нужно;
- подключение к интернету — обязательно при первом запуске, чтобы загрузить
  зависимости Python и frontend-тулчейн.

### Установка Python

1. Откройте [python.org/downloads/windows](https://www.python.org/downloads/windows/).
2. Скачайте 64-битный установщик одной из поддерживаемых версий Python
   **3.10–3.14**. Рекомендуется Python 3.14 x64.
3. Запустите установщик и **обязательно отметьте** пункт
   **Add python.exe to PATH**, затем нажмите **Install Now**.
4. После установки закройте и заново откройте командную строку.
5. Проверьте установку:

```bat
python --version
python -m pip --version
```

Версия Python должна находиться в диапазоне от 3.10 до 3.14.

### Установка Git

1. Откройте [git-scm.com/download/win](https://git-scm.com/download/win).
2. Скачайте и запустите установщик Git for Windows.
3. Все параметры можно оставить стандартными; добавление Git в `PATH` должно
   быть включено.
4. Откройте новую командную строку и проверьте:

```bat
git --version
```

### Установка Node.js

1. Откройте [nodejs.org](https://nodejs.org/).
2. Выберите версию **LTS** и скачайте установщик для Windows x64 (`.msi`).
3. Установите Node.js со стандартными параметрами и добавлением в `PATH`.
4. Откройте новую командную строку и проверьте:

```bat
node --version
npm --version
```

Если Node.js не установлен, сначала попробуйте обычный запуск через
`start_dashboard.bat`: в большинстве случаев Reflex установит необходимые
frontend-инструменты самостоятельно.

### Как скачать проект

Рекомендуемый вариант — через Git:

```bat
git clone https://github.com/Yorr3625/-Excel.git
cd -Excel
start_dashboard.bat
```

Также проект можно скачать на GitHub через **Code → Download ZIP**, распаковать
архив и запустить `start_dashboard.bat`. Однако ZIP неудобно обновлять: новую
версию придётся скачивать и распаковывать вручную.

### Как обновлять проект

В веб-дашборде откройте пункт меню **Версия** и нажмите **Проверить обновления**.
Программа сверит `APP_VERSION` с версией в репозитории
[Yorr3625/-Excel](https://github.com/Yorr3625/-Excel), ветка `main`. Сетевой запрос
выполняется только после нажатия кнопки.

Если доступна новая версия, станет активной кнопка **Обновить**. Она безопасно
загрузит изменения только в чистую Git-копию проекта и выполнит fast-forward без
сброса или удаления локальных файлов. После успешного обновления дашборд
перезагрузит страницу. Если запущенный режим не поддерживает автоматический
перезапуск, закройте окно и снова запустите `start_dashboard.bat`.

Автоматическое обновление требует копии, скачанной через Git. В ZIP-копии можно
посмотреть локальную версию и журнал, но кнопка обновления сообщит, что Git-копия
недоступна.

Обновление не затрагивает `data/`, `config/` и статистику. При наличии локальных
изменений или собственных коммитов программа остановится и предложит выполнить
синхронизацию вручную. Не запускайте обновление, пока редактируете файлы проекта.

При необходимости обновите проект вручную. Перед этим закройте дашборд и в
командной строке перейдите в папку проекта:

```bat
cd /d "C:\путь\к\-Excel"
git pull --ff-only origin main
start_dashboard.bat
```

`start_dashboard.bat` при каждом запуске проверяет `requirements.txt`, поэтому
новые или изменившиеся Python-зависимости установятся автоматически. Локальные
письма, заказы, результаты и `config/mail.json` при обновлении не удаляются.

Если Git сообщает, что локальные изменения мешают обновлению, временно сохраните
их, загрузите новую версию и верните изменения:

```bat
git stash
git pull --ff-only origin main
git stash pop
start_dashboard.bat
```

## Версии и журнал обновлений

Текущая версия приложения указана в `modules/version.py` в переменной
`APP_VERSION`. В веб-дашборде её можно посмотреть в пункте меню **Версия**.
Там же отображается журнал из `CHANGELOG.md`, который работает без подключения
к интернету. Пункт **Версия** также позволяет вручную проверить GitHub и запустить
безопасное обновление.

Для каждого обновления используйте семантическую нумерацию `MAJOR.MINOR.PATCH`:

- `MAJOR` — несовместимые изменения;
- `MINOR` — новые возможности без поломки существующего поведения;
- `PATCH` — исправления ошибок и небольшие улучшения.

При выпуске новой версии сначала измените `APP_VERSION`, затем добавьте новую
запись в начало `CHANGELOG.md`:

```markdown
## [1.1.0] — ДД.ММ.ГГГГ

- Краткое описание изменения.
```

После этого закоммитьте изменения и отправьте их в GitHub. Пользователь сможет
увидеть номер версии и список изменений после проверки в пункте **Версия** либо
после обычного `git pull` и перезапуска `start_dashboard.bat`.

Python обновляется установкой новой поддерживаемой версии с
[python.org/downloads/windows](https://www.python.org/downloads/windows/) поверх
старой. После установки пересоздайте виртуальное окружение:

```bat
python --version
rmdir /s /q .venv
start_dashboard.bat
```

Node.js и Git обновляются запуском свежего установщика с их официального сайта
поверх установленной версии. Для Node.js выбирайте актуальную ветку **LTS**.

## Запуск

Консольная версия (как раньше, через `start.bat` или напрямую):

```
python main.py
```

Графический интерфейс (tkinter):

```
python gui.py
```

Веб-дашборд (Reflex):

На новом **Windows 10/11 x64** ПК проще всего запустить
`start_dashboard.bat` — он проверит версию Python, создаст виртуальное
окружение (`.venv`), установит проверенные версии зависимостей из
`requirements.txt` и запустит дашборд. Нужен только 64-битный Python
3.10–3.14 с галочкой **Add python.exe to PATH** и интернет при первом
запуске (Reflex загрузит frontend-тулчейн).

Если установка или запуск завершатся ошибкой, окно не закроется сразу, а
покажет понятное сообщение. Повторные запуски используют уже созданное
окружение.

Вручную на Windows выполняются те же шаги:

```
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m reflex run
```

На macOS/Linux веб-дашборд запускается так:

```
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m reflex run
```

Откроется на `http://localhost:3000` (бэкенд — на `:8000`). Внутри:
- **Dashboard** — сводная статистика (заказы за сегодня, магазины, маршруты);
- **Заказы** — загрузка Excel-файла и обработка; режим Город/Область
  определяется автоматически по содержимому файла, но его можно
  переключить вручную. Если файл уже обрабатывался, об этом
  предупредит плашка. Там же задаётся водитель по каждому маршруту —
  имя видно во вкладке «Вес» и в колонтитуле печатных листов маршрута
  («Маршрут №N (Водитель) - Район»);
- **Почта** — заказы, пришедшие письмом (см. раздел ниже);
- **Маршруты** — редактирование списков магазинов по маршрутам отдельно
  для `config/stores_city.json` и `config/stores_region.json`; при
  сохранении прежняя версия уходит в резервную копию, к ней можно
  вернуться через выпадающий список;
- **Вес** — учёт веса по позициям: наименование, количество ящиков,
  средний и точный вес (если позицию взвесили), необязательная привязка
  к заказу и маршруту, фильтры, редактирование и удаление с
  подтверждением, подсказка веса по истории и итоговая сумма по списку;
- **Трекинг** — движение машин по маршрутам (симуляция либо реальные
  данные от мобильной страницы водителя `/driver`);
- **История** — последние обработанные файлы;
- **Настройки** — поведение программы (`config/settings.json`) и подключение
  чата-помощника (ключ Anthropic API или Claude Code CLI);
- переключатель светлой/тёмной темы внизу сайдбара;
- плавающая кнопка чата-помощника внизу справа — на всех страницах, доступна
  любому, кто открыл сайт (в т.ч. по временной ссылке `share_dashboard.bat`).
  Обычный диалог с Claude (Sonnet или Haiku), без доступа к заказам, весу или
  настройкам — не может ничего изменить, только отвечает на вопросы.

Во вкладках tkinter GUI можно:
- выбрать файл и запустить обработку, видеть сводку и список последних
  обработанных файлов;
- редактировать настройки (`config/settings.json`) без ручной правки JSON;
- редактировать списки магазинов по маршрутам (`config/stores.json`);
- вести учёт веса во вкладке «Вес» — те же возможности, что и в
  веб-дашборде: привязка к заказу и маршруту, фильтры, редактирование,
  удаление с подтверждением, подсказка веса по истории.

## Временный доступ с другого устройства

`share_dashboard.bat` — быстрый способ открыть веб-дашборд с другого
компьютера или телефона, без настройки роутера и без выделенного сервера.

При первом запуске скрипт скачивает `cloudflared` (официальную утилиту
Cloudflare) в папку `tools/` — она не входит в git и не требует
регистрации для разовых временных ссылок. Дальше скрипт:

1. Собирает дашборд в режиме одного порта (`--env prod --single-port`,
   порт `8080`) в отдельном окне — так фронтенд и бэкенд работают через
   один и тот же адрес, что необходимо для туннеля;
2. Открывает временную ссылку вида `https://случайное-имя.trycloudflare.com`
   прямо в этом же дашборде — она доступна с любого устройства с
   интернетом.

Ссылка работает, пока открыты оба окна (дашборд и туннель), и меняется
при каждом новом запуске скрипта. Это не постоянный хостинг: закрытие
окон полностью останавливает доступ. Обычный локальный запуск через
`start_dashboard.bat` эту ссылку не создаёт и никак не использует.

## Заказы из почты

Дашборд умеет забирать заказы из входящей почты: страница **Почта**,
кнопка «Проверить почту» либо автопроверка раз в N минут, пока дашборд
открыт. Кнопка «Проверить соединение» отдельно проверяет вход в IMAP и доступ
к папке, но не ищет письма и не скачивает вложения. На странице показывается
время последней завершённой проверки.

Настройка: откройте страницу **Почта**, введите адрес ящика и **пароль
приложения**, затем нажмите «Сохранить и подключить». Для Gmail обычный пароль
не подходит — нужен отдельный ключ приложения (двухэтапная аутентификация должна
быть включена). Быстрая ссылка для его создания:
[myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords).
Ключ можно вставить с пробелами — программа уберёт их сама.

Настройки сохраняются локально в `config/mail.json`, этот файл не попадает в git.
Источники заказов и накладных берутся из `config/mail.example.json` при первом
подключении; если нужно изменить отправителей, их по-прежнему можно
скорректировать в `config/mail.json`. Ольга Соленкова добавлена как отдельный
источник заказов. Для источника **Бухгалтер** доступны дополнительные
направления накладных: **Молоко**, **Парус** и **Краймери**. Направление
определяется сначала по теме письма, затем по имени PDF: «ФМ 40» или «МДВ» —
«Молоко», «ПАРУС» — «Парус», «КРАЙМАР» или «КРАЙМЕРИ» — «Краймери». PDF без
этих обозначений остаётся в общем списке для ручной привязки.

Как это работает:
- ящик открывается **только на чтение**: письма не помечаются
  прочитанными и не удаляются;
- от источников заказов берутся вложения `.xlsx`, `.xlsm`, `.xlsb`, `.xls`,
  `.xltx` и `.xltm`, а от источников накладных — `.pdf`. Excel считается
  заказом, только если тема письма — **«Заказ ТС МОЛОКО»** (регистр и лишние
  пробелы не важны) и сам файл проходит проверку;
- каждое Excel-вложение **проверяется до обработки** — если тема не совпала
  либо файл не является заказом (прайс, накладная, битый файл), оно
  помечается «Не заказ» с причиной, и кнопки обработки у него не будет.
  Признак заказа в самом файле — сколько магазинов из справочника нашлось:
  у настоящего заказа это десятки, у постороннего — ноль;
- подходящий заказ кладётся в `data/orders/`, а PDF-накладная — в
  `data/invoices/`. Файлы не перезаписываются: вложение с совпадающим
  именем сохранится как «имя (2).xlsx» или «имя (2).pdf»;
- при открытии обработанного заказа предлагаются только накладные,
  полученные в день заказа или на следующий календарный день. Для режима
  «Город» это максимум один PDF с приблизительным названием «ФМ 40, МДВ»;
  для режима «Область» — максимум по одному PDF из групп «Кировское / Торез /
  Шахтерск», «Горловка» и «Макеевка / Харцызск». Регистр, знаки препинания,
  дополнительные слова и порядок городов в имени не важны. PDF другой даты,
  неизвестного типа и дубликаты групп остаются ниже для ручной привязки;
- письма и вложения кешируются локально на 14 дней. Уже известные IMAP UID
  не загружаются повторно, поэтому повторная проверка забирает только новые
  письма; привязанные накладные не удаляются по возрасту;
- автопроверка повторяет только временные сетевые и IMAP-сбои. Количество
  попыток и пауза задаются в `config/mail.json` параметрами `retry_attempts`
  и `retry_delay_seconds`; ручная проверка выполняется один раз;
- новые распознанные заказы показываются отдельным уведомлением и счётчиком
  рядом с пунктом **Почта**. Фильтр «Только непривязанные накладные» оставляет
  PDF, которые ещё не связаны с заказом;
- в карточке обработанного заказа непривязанную накладную можно найти по имени
  файла, источнику или теме письма и привязать вручную;
- ошибки подключения сохраняются локально в `data/mail_errors.json`. Журнал
  ограничен последними записями и не сохраняет адрес ящика или пароль, однако
  файл всё равно является локальными данными и не должен добавляться в git.

## Тесты

Покрыты:
- обработка заказа целиком — от очистки исходного файла до сохранения
  результата и лога (`excel_cleaner.py`, `route_finder.py`,
  `route_sheets.py`, `pipeline.py`, `config.py`, `output_writer.py`,
  `logger.py`, `reporter.py`);
- история обработок и объёма по маршрутам (`history.py`);
- учёт веса (`weight_log.py`): добавление, правка, удаление, привязка к
  заказу/маршруту, подсказка веса по истории, совместимость со старой
  книгой без этих колонок;
- водитель и район по маршруту, разбор номера маршрута из названия листа
  и колонтитул печатных страниц (`route_drivers.py`);
- данные от страницы водителя (`driver_data.py`), включая проверку
  того, что чужой идентификатор машины не уводит запись за пределы
  папки с данными;
- проверка присланного файла (`order_validator.py`): настоящий заказ,
  посторонний Excel, битый файл, не та программа;
- разбор писем (`mail_watcher.py`) — с поддельным IMAP-сервером, так что
  тесты не ходят в сеть.

Не покрыты тестами: окно на tkinter (`gui_app.py`), веб-дашборд
(`orders_dashboard/`) и симуляция движения (`tracking_sim.py`) —
проверяются вручную.

```
pip install -r requirements-dev.txt
pytest
```

## Сборка отдельного .exe

Нужен Python и pip с доступом в интернет (для установки PyInstaller).

Запустите:

```
build.bat
```

Готовый файл появится в `dist\ОбработкаЗаказов.exe`.

Перед первым запуском exe положите рядом с ним папку `config` с
`settings.json` и `stores.json` — папка `data` со всем содержимым
(`orders`, `processed_orders`, `logs`) создастся автоматически.
