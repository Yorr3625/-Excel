# Обработка заказов

Программа распределяет строки/столбцы заказа по маршрутам доставки,
раскрашивает адреса, создаёт отдельные листы по каждому маршруту и
ведёт лог обработки.

## Структура проекта

Файлы разложены по назначению: `config/` — то, что настраивает пользователь,
`data/` — то, что программа накапливает сама.

```
main.py               — запуск из консоли (интерактивный выбор файла)
gui.py                 — запуск графического интерфейса (tkinter)
rxconfig.py             — конфигурация веб-дашборда (Reflex, обязан быть в корне)
start_dashboard.bat      — запуск веб-дашборда в один клик
start.bat                 — меню консольной версии
build.bat                  — сборка .exe из tkinter-версии

config/                — настройки и справочники (в git)
  settings.json          — поведение программы
  stores.json             — магазины по маршрутам (консоль и tkinter GUI)
  stores_city.json         — магазины по маршрутам, режим «Город» (дашборд)
  stores_region.json        — магазины по маршрутам, режим «Область» (дашборд)

data/                  — рабочие данные (не в git, создаются автоматически)
  orders/                — сюда кладутся исходные файлы заказов
  processed_orders/       — сюда сохраняются обработанные файлы
  logs/                    — логи обработки
  uploaded_files/           — файлы, загруженные через веб-дашборд
  tracking_data/             — GPS-точки от страницы водителя
  processed_files.json        — история обработанных файлов
  volume_history.json          — объём по маршрутам для графика на Dashboard
  route_backups.json            — резервные копии списков маршрутов

modules/
  paths.py             — все пути проекта в одном месте
  config.py             — загрузка/сохранение config/*.json
  history.py             — история обработок и объёма по маршрутам
                           (общая для консоли, tkinter и дашборда)
  styles.py               — цвета заливки маршрутов
  file_selector.py         — выбор файла заказа в консоли
  excel_cleaner.py          — очистка исходного файла
  route_finder.py            — поиск и раскраска адресов
  route_sheets.py             — создание листов по маршрутам
  output_writer.py             — сохранение результата
  logger.py                     — запись лога
  reporter.py                    — вывод сводки (консоль/tkinter GUI)
  pipeline.py                     — полный цикл обработки + автоопределение
                                     режима Город/Область (detect_mode)
  gui_app.py                       — само окно приложения (tkinter)
  tracking_sim.py                   — симуляция движения машин
  driver_data.py                     — данные от мобильной страницы водителя

orders_dashboard/
  orders_dashboard.py  — веб-дашборд обработки заказов (Reflex)

tests/                 — тесты обработки, истории и данных водителя
```

Пути нигде не дублируются: если понадобится перенести папку, правится
только `modules/paths.py`.

Один заказ учитывается в статистике один раз. Повторная обработка того
же файла считается исправлением: суммы в `volume_history.json`
обновляются на месте, а дата и время первой обработки сохраняются —
поэтому старый заказ не попадает в «Заказы сегодня» и не удваивает
объём на графике.

## Запуск

Консольная версия (как раньше, через `start.bat` или напрямую):

```
python main.py
```

Графический интерфейс (tkinter):

```
python gui.py
```

Веб-дашборд (Reflex):

На новом ПК проще всего запустить `start_dashboard.bat` — он сам
создаст виртуальное окружение (`.venv`), поставит зависимости из
`requirements.txt` и запустит дашборд. Нужен только установленный
Python 3.10+ (с галочкой "Add python.exe to PATH" при установке) и
интернет при самом первом запуске (Reflex докачивает свой
frontend-тулчейн).

Вручную это те же шаги:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m reflex run
```

Откроется на `http://localhost:3000` (бэкенд — на `:8000`). Внутри:
- **Dashboard** — сводная статистика (заказы за сегодня, магазины, маршруты);
- **Заказы** — загрузка Excel-файла и обработка; режим Город/Область
  определяется автоматически по содержимому файла, но его можно
  переключить вручную. Если файл уже обрабатывался, об этом
  предупредит плашка;
- **Маршруты** — редактирование списков магазинов по маршрутам отдельно
  для `config/stores_city.json` и `config/stores_region.json`; при
  сохранении прежняя версия уходит в резервную копию, к ней можно
  вернуться через выпадающий список;
- **Трекинг** — движение машин по маршрутам (симуляция либо реальные
  данные от мобильной страницы водителя `/driver`);
- **История** — последние обработанные файлы;
- **Настройки** — поведение программы (`config/settings.json`);
- переключатель светлой/тёмной темы внизу сайдбара.

Во вкладках tkinter GUI можно:
- выбрать файл и запустить обработку, видеть сводку и список последних
  обработанных файлов;
- редактировать настройки (`config/settings.json`) без ручной правки JSON;
- редактировать списки магазинов по маршрутам (`config/stores.json`).

## Тесты

Покрыты:
- обработка заказа целиком — от очистки исходного файла до сохранения
  результата и лога (`excel_cleaner.py`, `route_finder.py`,
  `route_sheets.py`, `pipeline.py`, `config.py`, `output_writer.py`,
  `logger.py`, `reporter.py`);
- история обработок и объёма по маршрутам (`history.py`);
- данные от страницы водителя (`driver_data.py`), включая проверку
  того, что чужой идентификатор машины не уводит запись за пределы
  папки с данными.

Не покрыты тестами: окно на tkinter (`gui_app.py`), веб-дашборд
(`orders_dashboard/`) и симуляция движения (`tracking_sim.py`) —
проверяются вручную.

```
pip install -r requirements-dev.txt
pytest
```

## Сборка отдельного .exe

Нужен Python и pip с доступом в интернет (для установки PyInstaller).

Запустите:

```
build.bat
```

Готовый файл появится в `dist\ОбработкаЗаказов.exe`.

Перед первым запуском exe положите рядом с ним папку `config` с
`settings.json` и `stores.json` — папка `data` со всем содержимым
(`orders`, `processed_orders`, `logs`) создастся автоматически.
