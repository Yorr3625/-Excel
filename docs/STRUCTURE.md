# Структура проекта

## Обработка и учёт

`modules/` содержит сервисы: обработку Excel, заказы, загрузку, рейсы, возвраты, почту и резервные копии. Перенос интерфейса не меняет форматы данных и правила расчёта.

- `main.py` — консольный запуск, `gui.py` — Tkinter.
- `orders_dashboard/orders_dashboard.py` — входная точка Reflex, регистрация приложения, middleware и прежний класс `State`.
- `orders_dashboard/api/` — HTTP API: `common.py` проверяет доступ и назначения, `admin.py` обслуживает административный вход и скачивания, `driver.py` — водителя и общий кабинет машины, `loader.py` — грузчика. Маршруты собираются в `api/__init__.py`.
- `orders_dashboard/pages/` — разметка страниц: `workspace.py`, `orders.py`, `mail.py`, `routes.py`, `settings.py`, `reports.py`. Нужный класс `State` передаётся в функции явно, чтобы эти модули не импортировали входную точку приложения.
- `orders_dashboard/components.py` — общие компоненты без состояния, `icons.py` — иконки, `constants.py` — подписи и настройки представления, `theme.py` — токены оформления.
- `orders_dashboard/loading_page.py` и `vehicle_trips_page.py` — отдельные рабочие страницы загрузки и рейсов.
- `assets/` — CSS и JavaScript-кабинеты с офлайн-очередью.
- `modules/session_store.py` — общая реализация сессий сотрудников. Фасады `driver_sessions.py` и `loader_sessions.py` имеют независимые хранилища, прежние cookie и отдельные контракты выбора машины. Административные сессии остаются в `dashboard_sessions.py`.

## Правила зависимостей

Страницы используют компоненты и сервисы, API — сервисы и общие проверки доступа. Они не импортируют `orders_dashboard.orders_dashboard`. Входная точка связывает страницы с `State` и сохраняет совместимые экспорты старых имён. Класс `State` намеренно не переносится: его полное имя связано с существующими событиями Reflex.

В тестах подменяйте зависимость в модуле, который её использует. Например, HTTP-отгрузка находится в `orders_dashboard.api.driver`, а не во входной точке приложения. Тесты состояния по-прежнему обращаются к прежнему `State`.

## Данные и вспомогательные материалы

- `config/`, `data/`, `.runtime/` — рабочие данные, настройки и маршрутизация сервера. Они не являются мусором или кэшем сборки.
- `ui-mockups/` — актуальные образцы дизайна; сохраняются локально и не входят в Docker-контекст.
- `docs/archive/` — старые дизайн-планы и прототипы, сохранённые для справки.
- `tests/` — проверки Python и поведения JavaScript; в production-образ не копируются.

## Проверка изменений

Для отдельного изменения сначала запускается прицельный тест. Перед выпуском:

```sh
python -m pytest
node --check assets/driver-app.js
node --check assets/loader-app.js
git diff --check
git diff --stat
git status --short
```

После структурных изменений также требуется компиляция Reflex и проверка реального интерфейса на отдельной копии с демонстрационными данными. Очистка Docker не обновляет приложение: для публикации кода используется отдельный выпуск по `DEPLOYMENT.md`.
